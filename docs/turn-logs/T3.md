## Failures, credential rotation and database recovery

Initial lint/type checks caught long SQL lines and a test fake-module attribute
typing issue. These were corrected before any commit or push. The first offline
suite passed 139 tests. The initial local database run failed at connection
setup with connection refused on `127.0.0.1:54329`.

**The failing third-party driver traceback exposed the generated local
development password.** The value is deliberately omitted from this log. It was
never added to Git. It was rotated immediately in the dedicated
development PostgreSQL role and ignored password file.

Rotation used a freshly generated random value, `ALTER ROLE` sent through psql
standard input, an atomic private-file replacement and a preserved-volume
container recreation. No credential value was placed in shell arguments or
printed. Actual recovery output included the following.

```text
Development database credential rotated; value omitted
Container lai-dev-db-1 Recreated
Container lai-dev-db-1 Healthy
```

The connector now creates a temporary mode-0600 libpq passfile and passes only
its filename to the driver. The helper frame holding its contents returns before
connection begins. The file is removed after the attempt, and errors are raised
with a fixed code and suppressed driver context. The offline regression test
checks driver arguments, traceback redaction, permissions and cleanup with an
invented sentinel. The active credential is absent from tracked/non-ignored files.

Connectivity diagnostics selected only state and port metadata from Docker.

```text
Host port configuration: {"5432/tcp": [{"HostIp": "127.0.0.1", "HostPort": "54329"}]}
Runtime published ports: {"5432/tcp": null}

```

A preserved-volume recreation reproduced that condition. The database listened
on port 5432 inside its healthy container. The internal network had no host TCP
publication. A private socket bind under `.local/postgres-socket` supplies a
working local path while the database uses its internal network.

```text

```

Setup now ensures `.local/` is mode 0700, including when uv creates it first.
The credential file remains mode 0600. A regression test exercises a fresh
initial mode-0755 directory and checks the corrected permissions. Existing data
volumes were preserved throughout. No live production credential was accessed.
